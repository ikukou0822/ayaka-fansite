## 檔案說明

| 檔案 | 用途 |
| --- | --- |
| `index.html` | 頁面骨架。文字都不寫在這裡，由 `app.js` 從 `data.js` 填入（只有 `<title>`、分享預覽的 meta、`<noscript>` 是固定文字） |
| `styles.css` | 樣式：白色系、手機優先、字級與留白系統、深色模式、減少動態效果、404 頁 |
| `nojs.css` | 瀏覽器停用 JavaScript、或 `data.js` 載入失敗／有語法錯誤時載入：只留下提示、頁首圖示與主視覺照片，不顯示空白的骨架 |
| `app.js` | 把 `data.js` 的內容畫到畫面上、語言切換、生日倒數、相簿（活動照片＋視訊回憶）放大檢視、WebP 圖片、分享按鈕、被 iframe 嵌入時隱藏內容、資料壞掉時退回 `nojs.css` |
| **`data.js`** | **所有文字與資料都在這裡；要改內容只需改這個檔案** |
| `countdown.js` | 生日倒數的計算（以日本時間 JST 為準，可在 Node 測試） |
| `share.js` | 分享按鈕的純邏輯：決定分享網址（`canonical` 優先）、選擇分享方式（可在 Node 測試） |
| `photos/` | 活動照片 `ayaka-01.jpg`～`ayaka-09.jpg`（說明在 `photos.json`）、視訊回憶 `call-01.jpg`～`call-09.jpg`（說明在 `call-photos.json`）、每張的 WebP 版本（`-480`／`-800`／`-1024`／`-full`）、分享預覽圖 `og.jpg` |
| `favicon.svg`、`icons/` | 原創的小圖示（花朵＋彩虹）與 PNG 版本（manifest／iOS 用） |
| `manifest.webmanifest` | 加到手機主畫面時用的設定 |
| `404.html` | 找不到頁面時顯示 |
| `.nojekyll` | 讓 GitHub Pages 直接發布檔案，不經 Jekyll 處理 |
| `scripts/make_images.py` | 換照片後重新產生 WebP 與 `og.jpg`（`--match 'call-*.jpg'` 可只處理某一組） |
| `scripts/import_photos.py` | 把新照片（PNG／JPEG）裁成 4:5、去除中繼資料，存成 `photos/前綴-01.jpg`…（換照片一律先用它處理；視訊回憶照片就是這樣做的） |
| `scripts/qa.js` | 品質檢查（headless Chromium 截圖與各項自動檢查） |
| `test/` | `node --test` 的測試：倒數邏輯與 `data.js` 資料完整性 |
| `package.json` | 只用來跑測試與品質檢查（網站本身不需要 npm） |

## 用 GitHub Pages 發布

1. 打開這個 repo 的 GitHub 頁面，點上方的 **Settings**。
2. 左側選單點 **Pages**。
3. 在 **Build and deployment** 的 **Source** 選「**Deploy from a branch**」。
4. **Branch** 選 `main`，資料夾選 `/ (root)`，按 **Save**。
5. 等 1～2 分鐘，頁面上方會出現網址：`https://dc9408222000-hub.github.io/ayaka-fansite/`。
6. 勾選 **Enforce HTTPS**。

之後每次 push 到 `main`，GitHub Pages 都會在一兩分鐘內自動更新。

> 製作時的環境沒有權限呼叫 GitHub 的 Pages API 自動開啟，所以需要照上面的步驟手動開啟一次。

## 怎麼改內容（全部在 `data.js`）

`data.js` 裡每一段文字都有 `ja`（日文）和 `zh`（繁體中文）兩個版本。改完存檔、commit、push 到 `main` 就會更新。
改完請先執行 `node --test`：少一個逗號或引號沒關好時，第一個測試就會失敗並指出行號；沒有漏掉某一種語言也會一起檢查。
（萬一壞掉的 `data.js` 被 push 出去，網站只會顯示字標與主視覺照片，不會出現空白的骨架，但其他內容都看不到。）

### 應援標語、首頁文字

`hero.slogan` 是首頁的應援標語（目前是範例，請換成自己的話）；`hero.eyebrow` 是標語上方的小字。

```js
slogan: {
  ja: 'その笑顔が、今日もわたしの元気のもと。',
  zh: '妳的笑容，是我每一天的元氣來源。'
},
```

### 個人資料

`profile` 陣列裡每一筆是一個欄位。`value: null` 會顯示「準備中／待補」，確認之後改成文字即可：

```js
{ label: { ja: '出身地', zh: '出身地' }, value: { ja: '〇〇', zh: '〇〇' } },
```

### 年表

在 `timeline` 陣列加一筆。`date` 可以寫 `'2027-01-01'`、`'2027-01'` 或 `'2027'`，不確定日期就寫 `null`。
`{ placeholder: true }` 是畫面上「之後會陸續補上」的空白欄位，不需要時可以刪掉。

```js
{
  date: '2027-01-01',
  title: { ja: '出来事のタイトル', zh: '事件標題' },
  note:  { ja: '補足（不要なら空文字）', zh: '補充說明（不需要可留空）' }
},
```

### 應援留言

`messages` 陣列裡每一筆是一張留言卡（目前是 4 則範例，請換成自己的話），建議 3～5 則。

### 分享按鈕（「關於本站」區塊最後）

文字都在 `ui` 裡，鍵名以 `share` 開頭：

| 鍵名 | 用途 |
| --- | --- |
| `ui.shareLead` | 按鈕上方的一句引導文字 |
| `ui.shareButton` | 按鈕文字（「このサイトをシェア／分享這個網站」） |
| `ui.shareText` | 手機的系統分享選單裡，附在網址旁的一句說明（請保持簡短） |
| `ui.shareCopied` | 複製網址成功後顯示幾秒的提示 |
| `ui.shareCopyManual` | 無法自動複製時，顯示在網址前面的說明 |

分享的標題用 `site.title`；網址一律取 `index.html` 裡 `<link rel="canonical">` 的絕對網址（之後改用自訂網域時請一併修改）。

### 其他設定（`site`）

- `lastUpdated`：頁尾的「最後更新」日期（`YYYY-MM-DD`）。
- `defaultLang`：預設語言（`'ja'` 或 `'zh'`）。
- `birthday`：生日（倒數以日本時間計算）。
- `webp`：是否使用 WebP 圖片（換照片後還沒重新產生 WebP 時先改成 `false`）。
- 想預覽「生日當天」的畫面：在網址後面加 `#birthday-preview`（只在本機預覽時有效：`127.0.0.1`、`localhost` 或直接開啟檔案；正式網址上不會生效，別人貼「假生日」連結也沒有用）。

## 換照片

**新照片一律先用 `scripts/import_photos.py` 處理**：它會裁成 4:5 直式、去除 GPS／EXIF 等中繼資料，再存成 `photos/前綴-01.jpg`…。
`node --test` 會要求相簿每張照片都剛好是 4:5（容差 0.002），自己裁的圖很容易過不了。需要 Python 3 與 Pillow（`pip install Pillow`）。

1. 把新圖放在任一資料夾（檔名排序就是順序），裁切＋去除中繼資料＋產生 WebP 一次做完：

   ```bash
   python3 scripts/import_photos.py 來源資料夾 --prefix ayaka   # 活動照片；視訊回憶用 --prefix call
   python3 scripts/make_images.py --match 'ayaka-*.jpg'         # 只為這一組產生 -480 / -800 / -1024 / -full.webp
   ```

   `import_photos.py` 預設固定上緣、只裁掉下方多餘的部分（`--anchor center` 可改成置中）。
   `make_images.py` 會為每張照片產生 `-480.webp`、`-800.webp`、`-1024.webp`、`-full.webp`；不加 `--match` 會處理全部 `photos/*.jpg`，並從 `photos/ayaka-07.jpg` 裁出 `photos/og.jpg`（分享預覽圖，想換來源請改腳本裡的 `OG_SOURCE`）。
   暫時不想處理 WebP 的話，把 `data.js` 的 `site.webp` 改成 `false` 即可。
2. 在 `data.js` 改照片資料：活動照片在 `photos` 陣列（`src`、`date`、`alt_ja`、`alt_zh`、`width`、`height`），視訊回憶在 `callPhotos.items`（日期是整組共用的 `callPhotos.date`）。首頁主視覺是 `hero.photo`。
3. 對照用的原始檔也一起更新：`photos/photos.json`（活動照片）、`photos/call-photos.json`（視訊回憶，`node --test` 會檢查它和 `data.js` 的 `callPhotos` 完全一致）。
4. 執行 `node --test`，會檢查照片檔案與 WebP 版本都存在、`width`／`height` 和 JPEG 實際尺寸一致、每張都是 4:5。

## 本機預覽

直接用瀏覽器打開 `index.html` 就能看。想和 GitHub Pages 一樣用網址瀏覽：

```bash
python3 -m http.server 8000 --bind 127.0.0.1
```

然後打開 <http://127.0.0.1:8000/>。`--bind 127.0.0.1` 讓預覽只有自己的電腦看得到；少了它，同一個 Wi-Fi 上的其他人也能瀏覽整個資料夾（包括 `.git/`）。

## 安全說明摘要

網站是純靜態、沒有後端、沒有表單、不收集任何資料，也不載入任何第三方資源。
每個頁面都有嚴格的 Content-Security-Policy，所有程式與樣式都放在獨立檔案，寫入畫面只用 `textContent`，
被別的網站用 iframe 嵌入時會隱藏內容、只留下開啟連結（GitHub Pages 無法設定 frame 相關標頭，所以無法完全禁止嵌入）。細節請看 [SECURITY.md](SECURITY.md)。

## 帳號安全建議

- GitHub 帳號開啟 **兩步驟驗證**：Settings → Password and authentication → Two-factor authentication（建議用 passkey 或 authenticator app，並保存 recovery codes）。
- Pages 設定勾選 **Enforce HTTPS**：Settings → Pages。
- 保護 `main` 分支（禁止 force push 與刪除）：Settings → Rules → Rulesets → New branch ruleset，目標 `main`，勾選「Block force pushes」與「Restrict deletions」。
- Settings → Emails：勾選「Keep my email addresses private」與「Block command line pushes that expose my email」，避免 commit 帶出個人信箱。
